# Agent-Ab 固定设计流程

在用户要求运行、续跑或核对 Agent-Ab 设计任务时使用。蛋白质功能、论文原理和概念解释按咨询问题直接回答。项目路径、命令、暂停状态和结果核对见 [执行参考](references/execution.md)。

## 先判断用户要做什么

| 用户的输入与目标 | 选择的路线 |
| --- | --- |
| 提供靶标结构，要求从头设计 Binder、抗体或纳米抗体 | 确认设计类型、靶标链、hotspot 和所需 framework，走固定 `pipeline`。工具和阶段以确认的任务 spec 与站点配置为准。 |
| 已有骨架，要求用 ProteinMPNN 或 AbMPNN 设计序列 | 核对待设计链、固定残基和现有环境。使用已确认的单项序列设计入口，交付序列与生成记录。入口或输入缺失时，说明具体缺项。 |
| 已有设计序列或候选结构，要求筛选 | 先对齐候选 ID、结构、序列和已有评分。按用户要求复用已计算结果或执行已配置的预测与筛选步骤。 |
| 已有父本，要求突变或亲和成熟优化 | 确认父本、允许改动的位置和采样范围。已有 run 的 IgGM 按保存的启用条件执行。独立 IgGM 成熟任务按实际 `iggm-mature` 接口提供关联的 `run_id`、父本输入和经确认的参数。 |
| 提供已有 `run_id`，要求继续或查看进度 | 先读 `status`、`parts` 与保存的 `spec.json`。续跑用原 `run_id`，查询进度时只读状态与产物。 |

各单项请求按所需步骤执行。研究 Agent 的 `agent-create`、`agent` 用于独立 Stage 1 研究任务。固定端到端任务使用 `pipeline`。

## 固定 Pipeline 的顺序与通过条件

| 步骤 | 什么时候进入下一步 |
| --- | --- |
| 1. 环境与输入预检 | 首次部署先检测软件、环境、权重和数据，列出缺项及获取方式。已部署项目用 `doctor` 核对环境。确认 PDB、链、残基编号、hotspot、framework、设计类型和范围后，用 `validate` 和 `plan` 建立新任务。 |
| 2. 骨架生成与选择 | 沿用 spec 选定的骨架工具和几何门槛。需选 Top‑N 时，读取 `action_required`、排序表和允许范围，使用用户给定或已保存的选择。 |
| 3. 序列设计与侧链装配 | 对通过骨架条件的候选执行已配置的序列设计与侧链装配。核对固定残基、原始候选编号和输出数量。 |
| 4. 结构预测 | 确认预测所需输入齐全，按保存的工具配置运行。根据 manifest 核对预测覆盖率和输出完整性。 |
| 5. 评分与筛选 | 依据原有结构与界面指标、阈值和候选配对判断通过情况。零候选时按程序的实际终止状态交付。 |
| 6. 按范围继续后续阶段 | `full` 任务按已启用条件进入 Stage 2、FastRelax、负靶筛选、IgGM 和 Stage 3。依据各阶段的通过结果及程序状态推进。 |
| 7. 核对并交付 | 从状态、manifest、筛选表和 `result_paths` 核对实际终点、数量及文件。报告原编号、结构或序列路径，以及暂停、失败或续跑所需的信息。 |

让原 Pipeline 负责阶段编排。预览使用 `pipeline --dry-run`。遇到 `action_required` 时按提示补齐必要输入。确认前一次执行已经退出后，再续跑同一任务。

## 执行红线

- **保护原始输入和结果。** 将原始 PDB 作为只读输入。新任务使用新任务名，已有任务保留原始候选编号、输出目录和已完成产物。
- **沿用确认过的设计参数。** 靶标链、hotspot、framework、固定残基、seed、采样策略和筛选阈值以经确认的 spec 为准。参数或范围需要变更时先由用户明确指定。
- **按授权执行计算。** 整理 Skill、解释流程和检查状态时使用相应的只读入口。首次配置缺项时先列出获取方式，安装采用已授权的来源。
- **失败时保留证据。** 记录失败阶段、返回码和日志，暂停依赖该输出的后续步骤。确定原因、恢复条件和适用范围后，再用项目支持的恢复方式继续。
- **按实测或实际计算记录报告。** 评分只引用可追溯的结果。缺失阶段标明未完成，IgGM FASTA 按序列变体计数。实验亲和力只依据实验数据报告。
